# Entity types

Colander defines eight types of entities. Each type has sub-types, for example *Observable / IP v4* or *Artifact / Android backup*. The relationships listed for each type are *tight relationships*: they are set from the attributes of the entities, follow the ontology of Colander, and cannot be edited in the graph editor, where they are marked with a padlock. To learn why Colander codifies knowledge this way, see [Knowledge management](/docs/explanation/colander/knowledge-management).

Custom attributes can be added to artifacts, devices, observables and events. Some sub-types, such as *IP v4*, come with suggested attributes such as *address block* or *asn*.

## Actors
Entities of this type represent individuals, organizations or groups that can perform actions in the digital environment.

<CaptionedImage src="/img/colander/entity_management/actor.png" alt="Create a new actor" caption="Create a new actor" align="center"/>

### Tight relationships

* *Device* is operated by an *Actor*
* *Observable* is operated by an *Actor*

## Artifacts
Entities of this type represent files or any digital trace left behind by actors or the execution of a software.

<CaptionedImage src="/img/colander/entity_management/artifact.png" alt="Create a new artifact" caption="Create a new artifact" align="center"/>

### Tight relationships

* *Artifact* has been extracted from a *Device*
* *Observable* has been extracted from an *Artifact*
* *Event* has been been extracted from an *Artifact*
* *Fragment of data* has been extracted from an *Artifact*

## Devices
Entities of this type represent computers, smartphones, tablets, and other electronic devices that store and transmit data.

<CaptionedImage src="/img/colander/entity_management/device.png" alt="Create a new device" caption="Create a new device" align="center"/>

### Tight relationships

* *Device* is operated by an *Actor*
* *Event* has been observed on a *Device*
* *Artifact* has been extracted from a *Device*

## Detection rules
Entities of this type represent sets of criteria used to identify suspicious activity or potential threats.

<CaptionedImage src="/img/colander/entity_management/detection_rule.png" alt="Create a new detection rule" caption="Create a new detection rule" align="center"/>

### Tight relationships

* *Event* has been detected by a *Detection rule*

## Threats
Entities of this type represent potential risks or harmful actions that can target individuals, organizations, or systems.

<CaptionedImage src="/img/colander/entity_management/threat.png" alt="Create a new threat" caption="Create a new threat" align="center"/>

### Tight relationships

* *Observable* indicates a *Threat*

## Observables
Entities of this type represent specific pieces of evidence or information that can be used to identify a technical information.

<CaptionedImage src="/img/colander/entity_management/observable.png" alt="Create a new observable" caption="Create a new observable" align="center"/>

### Tight relationships

* *Observable* is operated by an *Actor*
* *Observable* has been extracted from an *Artifact*
* *Observable* indicates a *Threat*
* *Event* involves a set of *Observable*

## Events
Entities of this type represent recorded occurrences of actions or changes in a system.

<CaptionedImage src="/img/colander/entity_management/event.png" alt="Create a new event" caption="Create a new event" align="center"/>

### Tight relationships

* *Event* involves a set of *Observable*
* *Event* has been detected by a *Detection rule*
* *Event* has been been extracted from an *Artifact*

## Fragment of data
Entities of this type represent small pieces of data that can be used to reconstruct a larger dataset or provide insights into the activities of actors or systems.

<CaptionedImage src="/img/colander/entity_management/fragment.png" alt="Create a new fragment of data" caption="Create a new fragment of data" align="center"/>

### Tight relationships

* *Fragment of data* has been extracted from an *Artifact*
